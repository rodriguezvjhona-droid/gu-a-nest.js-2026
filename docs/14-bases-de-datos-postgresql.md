# 14. Bases de datos: diseñar y conectar PostgreSQL

## Separar responsabilidades

Una base de datos relacional almacena datos en tablas. En una API habitual:

- PostgreSQL ejecuta y conserva las tablas.
- Un driver de Node.js habla el protocolo del motor (`pg` para PostgreSQL).
- TypeORM o Prisma mapea operaciones de aplicación a consultas.
- El paquete `@nestjs/typeorm` integra repositorios/data sources en DI de Nest.
- Un service aplica reglas de negocio y usa repositorios; el controller no debe construir SQL ni conectarse directamente.

La base de datos y el framework son piezas distintas: Nest puede usar otros motores/ORM o un driver directo.

## Diseñar las tablas antes del código

En el ejemplo de catálogo se usan estas tablas:

```text
categories
  id              PK, entero autogenerado
  name            texto único y obligatorio

products
  id              PK, entero autogenerado
  name            texto obligatorio
  description     texto opcional
  price_in_cents  entero no negativo
  category_id     FK -> categories.id, obligatorio
```

Relación: una categoría tiene muchos productos; cada producto pertenece a una categoría (`1:N`). Guardar el precio como centavos enteros evita errores de aritmética binaria de punto flotante en dinero. En sistemas financieros reales diseña cuidadosamente tipo/escala monetaria y redondeo.

Reglas de esquema:

- Usa una clave primaria por tabla.
- Marca requeridos como `NOT NULL` y valores únicos con una restricción de base de datos.
- Declara claves foráneas para mantener relaciones válidas.
- Elige la acción al borrar (`RESTRICT`, `CASCADE`, etc.) según la regla de negocio; el ejemplo protege categorías con productos.
- Añade índices según consultas reales, no por intuición.

## Crear PostgreSQL local con Docker

```yaml
# docker-compose.yml
services:
  db:
    image: postgres:18
    container_name: nest_catalog_db
    restart: unless-stopped
    environment:
      POSTGRES_DB: catalog_db
      POSTGRES_USER: catalog_user
      POSTGRES_PASSWORD: local_dev_password
    ports:
      - "5432:5432"
    volumes:
      - catalog_data:/var/lib/postgresql/data
      - ./db/init.sql:/docker-entrypoint-initdb.d/001-init.sql:ro
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U catalog_user -d catalog_db"]
      interval: 5s
      timeout: 3s
      retries: 10
volumes:
  catalog_data:
```

```sql
-- db/init.sql; PostgreSQL ejecuta esto solo al inicializar un volumen vacío.
CREATE TABLE categories (
  id integer GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  name varchar(100) NOT NULL UNIQUE
);

CREATE TABLE products (
  id integer GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  name varchar(100) NOT NULL,
  description varchar(500),
  price_in_cents integer NOT NULL CHECK (price_in_cents >= 0),
  category_id integer NOT NULL REFERENCES categories(id) ON DELETE RESTRICT
);

INSERT INTO categories (name) VALUES ('Bebidas'), ('Accesorios');
```

Arranca la base desde la carpeta del proyecto:

```bash
docker compose up -d db
docker compose ps
```

El archivo init solo se ejecuta cuando el volumen aún está vacío. Para cambios posteriores utiliza migraciones; no borres un volumen de datos real para volver a inicializarlo.

## Variables de entorno

```dotenv
# .env (local, no subir secretos reales)
PORT=3000
DATABASE_URL=postgres://catalog_user:local_dev_password@localhost:5432/catalog_db
```

Incluye `.env` en `.gitignore`. En producción usa el gestor de secretos de la plataforma. La URL de ejemplo solo es una credencial de desarrollo local.

## Dependencias

Desde la raíz de un proyecto creado con Nest CLI:

```bash
npm install @nestjs/config @nestjs/typeorm typeorm pg
npm install class-validator class-transformer
```

Instala versiones compatibles con el major de Nest elegido. En octubre de 2026, el paquete oficial `@nestjs/typeorm` 12 declara compatibilidad con Nest 10/11/12 y TypeORM 0.3 o 1.x; la versión exacta puede avanzar, así que consulta el [paquete oficial](https://github.com/nestjs/typeorm) al instalar.
